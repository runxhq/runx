# Runx CLI 0.6.1

Runx 0.6.1 routes every effect through one kernel, adds an opt-in managed agent
and governed HTTP, and lets anyone verify a receipt store offline.

## Highlights

- An effect kernel: effects dispatch through registries and settle under
  generic guards, and payments are ordinary effect records.
- `runx verify` checks a sealed receipt store offline: it groups receipts into
  lineage trees and re-verifies digests, content addresses, tree integrity and,
  with trusted keys, Ed25519 signatures. A broken chain fails closed.
- An in-process managed agent, opt-in, with an Anthropic model caller and a
  tool executor that calls back into the governed runtime.
- Governed HTTP: an HTTP skill source and a first-class HTTP tool source, with
  `PUT` and `PATCH`, URL path templates and local credentials delivered to
  graph HTTP steps.

## Added

- The governed MCP server over streamable HTTP.
- `runx harness <skill>` runs the harness a skill declares inline.
- `runx publish` publishes a receipt with a signed identity.
- `runx export` writes runnable host-agent shims that can resume agent tasks.
- A `when` branch primitive for graphs, and graph stages named as skill refs.
- Official skills resolve from local registries.
- External-adapter, OpenAPI and HTTP skill fronts, and a thread outbox that
  publishes GitHub issues.
- Payment rail settlement finality, a durable cross-run spend ledger, a Stripe
  shared payment token path and an x402 interop preflight.
- Skill context injection for agent steps.
- Examples: a governed-spend demo with an offline receipt verifier, a GitHub
  MCP walkthrough, loop orchestration and a public weather provider.

## Fixed

- Approval answers are routed by the declared `gate_id`, not the step id.
- A directory counts as a skill package only when it holds `SKILL.md` or
  `X.yaml`.
- A skipped `when` branch still seals its graph.
- Process limits are portable to Linux `sh`.

## Security

- Capability admission was hardened, and payment proof and spend-cap
  fail-open gaps were closed.
- MCP tool scopes are enforced.
- Receipt verification requires trusted keys, and credential delivery
  references are sealed.
- The repository runs cargo-deny advisories, Dependabot and secret scanning,
  and publishes a security policy and code of conduct.

## Breaking changes

- Graph stages must be skill refs; the legacy stage forms are refused.
