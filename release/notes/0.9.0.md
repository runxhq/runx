# Runx CLI 0.9.0

Runx 0.9.0 consolidates local skill execution and removes obsolete execution
surfaces. CLI and MCP hosts use the same local orchestration boundary, with
persistent continuation state and an adjacent JavaScript worker. This is a
minor-version upgrade with explicit cutovers for consumers of retired internals.

## Highlights

- One local orchestration owner for skill execution, waiting state and resume.
- Reuse of admitted execution closures and a session JavaScript worker.
- Local operator ownership stays in OSS when hosted provider connectors are used.
- Packaged selector checks cover both CLI and worker integrity.
- Runx is licensed under Apache-2.0, as it was before 0.6.0; releases 0.6.0
  through 0.8.2 were MIT.
- Paid invocations: the `runx.paid-invocation.v1` contracts, paid skill
  listings, and x402 v2 behind a pinned contract boundary.

## Added

- Skills: `schema-guard` (a compatibility gate), `purchase-approval` (a
  pre-spend gate), `data-subject-request` (a privacy gate), `contract-drafter`,
  `sbom-maker`, `crm-cleanup`, `postmortem-maker`, a governed overlay over an
  open-ecosystem skill, and `incident-commander`.
- The `runx.paid-invocation.v1` contracts: quotes, request fingerprint binding,
  offer terms, results, failures and artifact reads, published from
  `@runxhq/contracts`, with paid skill listings bound to exact executors and
  vendor pricing.
- x402 v2 behind a pinned contract boundary, a TypeScript presentation kit and
  an inert discovery projection, and external x402 JSON resources.
- Durable external job contracts, with paid external job mutations admitted by
  the runtime.
- Principal-scoped hosted artifacts with approved handoff to another principal.
- Connect: bring-your-own credentials read from stdin, and retained credential
  grants are reused.
- An act seals the reason an operator wrote in its input.
- Strict composite proof contracts for receipts.
- Cross-process local continuation coverage and concurrent worker-spawn coverage.
- Explicit package and dependency ownership checks for the surviving SDK,
  contract and native execution boundaries.

## Changed

- CLI and MCP skill fronts use the canonical local orchestrator and typed
  lifecycle outcomes.
- Local continuation state uses atomic private files without raw credentials.
- Contract equivalence uses one native batch of scope cases; test setup no
  longer launches a native process for each mirrored case.
- Release checks retain real platform and packaging boundaries while removing
  repeated preparation and obsolete source-text assertions.

## Fixed

- Empty scope patterns no longer act as wildcards.
- Concurrent macOS worker launches no longer inherit another launch's temporary
  pipes, which could otherwise hold process completion open.
- CLI and JavaScript worker digests are checked before packaged execution.

## Removed

- `runx payment admission issue`, the `runx-pay` crate and the governed-spend
  examples: payment rail execution runs behind the hosted boundary, and OSS
  keeps the payment contracts.
- The `messageboard` skill.
- The unused `public_work` evaluator, associated contract types and fixtures.
- Parallel local skill orchestration paths and obsolete compatibility exports.
- Duplicate corpus and historical implementation-name checks whose current
  contract has an executable proof owner.

## Security

- Scope narrowing and approval provenance remain native runtime responsibilities.
- Continuations retain private file permissions and exclude raw credentials.
- The CLI distribution includes the matching authority-free JavaScript worker;
  internal Rust libraries are not published by a CLI release.

## Breaking changes

- Consumers of the retired `public_work` surface must move to current native
  skill/graph execution; no compatibility evaluator remains.
- Embedders using retired internal orchestration/export paths must use the
  current owning module. The CLI and MCP fronts share the local orchestrator.
- Execution closure identity includes the runtime release. Reinspect packages
  and obtain the current execution closure when moving to 0.9.0; do not reuse
  a release-bound invocation identity from another runtime version.

## Upgrade guidance

- Once this candidate is published, install with
  `npm install --global @runxhq/cli@0.9.0` or the corresponding package-manager
  channel, and confirm `runx --version` reports `0.9.0`.
- Install the CLI and its matching worker together. Keep local operator state
  local unless an explicit hosted operator service is selected.
- Reinspect affected skills and update callers of retired internal paths.
- Cloud operators must follow the separate hosted receipt-custody and approval
  pagination cutover guidance. CLI installation alone does not migrate Cloud
  receipt ownership or deploy the hosted service.
