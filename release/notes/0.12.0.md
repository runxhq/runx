# Runx CLI 0.12.0

This release changes Runx's package, connector, authority and local-state
contracts together. It adds resumable scripted workflows, explicit context
and memory boundaries, and reuse of eligible recorded reads. Upgrade the CLI,
packages and hosted consumers as one coordinated cutover.

## Highlights

- Scripted workflows retain settled calls across interruption and resume.
- Revisions can reuse eligible read results while changed inputs recompute.
- Confirmed personal words and untrusted observations have separate memory
  streams, with bounded indexes, search and exact reads.
- Publication promotes the exact archives and npm tarballs tested in a
  successful release rehearsal.

## Added

- Native workspace identity and saved authority boundaries.
- Explicit agent execution requirements and context-sharing labels.
- Resumable waits and concurrent calls within declared scripted workflows.
- The bundled memory skill, with confirmation, correction, observation,
  disable, index, search and read methods.
- Criterion-bound verdicts and evaluation inputs that preserve their source
  attachments and subject identity.

## Changed

- Skills declare methods in `run.yaml`; invoke a selected method as
  `runx skill <reference>#<method>`.
- Connector manifests use named operations, explicit verbs, leases and exact
  bindings. Native inspection owns the exposed method and operation contracts.
- Provider idempotency binds the authorized intent, including calls made
  through composed workflows.
- Recorded read reuse checks the source, authority, inputs and implementation
  before admitting a result into a new run.
- The default host interface yields admitted turns. Managed model execution
  remains an explicit per-run choice.
- The Python client is released as `runx-py` 0.1.3 with the 0.12 invocation
  and continuation contracts.

## Fixed

- A revised workflow holds an uncertain prior send for reconciliation while
  unrelated work can continue.
- Returned host-call results survive the tested power-loss boundary.
- Null input values, paged context and source bindings survive their native
  input and continuation boundaries.
- Output validation reports actionable field paths without echoing the full
  rejected payload into each repair attempt.
- Builder results retain the decision rationale and recovery context when no
  package is created.

## Removed

- Old package and connector shapes, compatibility readers and obsolete CLI
  entry points. `runx test` is the package-test surface.
- The Rust SDK and x402 crates, extension SDK and LangChain package removed
  by the 0.12 architecture cutover.
- Per-run ledger files and package-local copies of runtime-owned execution
  mechanisms.

## Security

- Package signatures bind the bytes used for execution; publisher identity
  does not come from a package's own name or prose.
- Explicit unknown arguments are refused. Context that cannot cross a
  sharing boundary is refused instead of silently omitted.
- Confirmed memory requires its confirmation boundary. An observation remains
  untrusted evidence and grants no additional authority.

## Breaking changes

- Pre-0.12 package, connector and hosted API contracts are incompatible with
  this release. Old public CLIs cannot use the converted registry API.
- Local stores and run state from earlier runtime versions are not migrated.
  A new runtime refuses incompatible state rather than partially reading it.
- Suspended runs retain their implementation binding; a changed runtime or
  worker is not an interchangeable continuation driver.
- Previously signed receipts remain unchanged. Retain the CLI that wrote an
  old receipt for its verification; historical hosted receipt pages preserve
  their original documents.

## Upgrade guidance

1. Finish or deliberately stop outstanding work before upgrading. Preserve
   prior state and receipts; do not delete them to make the new runtime start.
2. Move incompatible local state aside and start a fresh 0.12 store. No
   automatic carry of prior memory, social-operation state or replay keys is
   provided.
3. Reinstall converted registry packages. For source packages, use the
   [package converter](https://github.com/runxhq/runx/tree/cli-v0.12.0/tools/convert)
   and review any fields it refuses before running the converted package.
4. Refresh host exports with `runx export` and remove stale exports. Update
   integrations to the published 0.12 contracts and verify their selected
   methods, context and authority before resuming work.

Model quality and provider readiness remain specific to the tested model,
binding and journey. A sealed run or valid evidence binding alone is not
independent proof of a model's conclusions or an unobserved provider effect.
