# Runx CLI 0.8.0

Runx 0.8.0 consolidates the operator runtime around one native, governed
execution path. Skills remain rich knowledge artifacts for humans and agents,
while Runx owns context delivery, capability admission, credentials, process
containment, approvals, receipts, and provider readback end to end.

## Highlights

- Unified governed skill execution behind one Rust-owned runtime and evidence
  boundary, removing parallel execution and sealing paths.
- Preserved full operator and agent context through planning, approval,
  execution, continuation, and receipts instead of reducing runs to transport
  output.
- Reused isolated JavaScript workers with a bounded four-worker fanout pool,
  deterministic state isolation, and cross-platform process-tree ownership.
- Audited all 77 official skill manuals and their native runner value so skills
  describe real operator capability rather than duplicating generic agent work.
- Proved the release candidate across Apple Silicon, Intel macOS, Linux x64,
  Linux ARM64, and Windows x64, including optimized-worker smoke tests.

## Added

- Native, evidence-bound operator journeys for policy, ledger, payments,
  provider operations, receipts, and skill composition.
- Declared environment and authorization-scope passthrough across native and
  JavaScript execution without exposing undeclared host credentials.
- Slack attachment and permalink reads with bounded pagination and provider
  evidence.
- Governed Nitrosend provider operations through the canonical public skill.
- A retained runtime-quality artifact with exact-commit provenance, worker
  ownership metrics, stress evidence, and named diagnostics.
- Independent verification for every required synchronous release channel:
  GitHub Release, npm, GHCR, Homebrew, and Scoop.

## Changed

- Consolidated skill parsing, inspection, execution, provider effects, and
  receipt sealing around native runtime ownership.
- Made skill manuals the authoritative operator context while keeping
  JavaScript for genuine domain logic rather than request, HTTP, parser, or
  registry plumbing already owned by Runx.
- Made targeted Codex exports additive: exporting one skill no longer removes
  unrelated installed skills, and multi-runner skills no longer invent a fake
  default runner.
- Bound approvals to a single action owner and the exact normalized command or
  provider plan, reducing repeated approval prompts without weakening authority.
- Reused provider and worker clients, bounded cleanup, and separated
  deterministic concurrency proof from scheduler-sensitive performance
  sampling.
- Updated existing v1 contracts in place; 0.8.0 does not introduce a parallel
  v2 contract family.

## Fixed

- Windows process-tree containment, wrapper policy, timeout semantics, and
  non-blocking cleanup.
- Strict Linux sandbox and execution contracts, including reproducible
  clean-checkout gates.
- macOS sandbox child-process supervision and workspace-local package caches,
  so governed builds can terminate their own workers without gaining host-wide
  signal or filesystem authority.
- Verified JavaScript worker cold starts, session reuse, state isolation, and
  bounded parallel fanout.
- MCP fixture packaging and native service construction at the unified runtime
  boundary.
- Duplicate and drifting execution ownership across CLI, runtime, provider,
  and receipt surfaces.
- Twitter archive-plan identity and successful unfollow recognition.
- Empty Slack pagination cursors and redundant GitHub thread readbacks.
- Winget worker-path rendering, shared Linux sandbox setup, release artifact
  evidence, and fail-closed package-manager publication.
- Authenticated, hour-bounded release readback for real multi-platform builds,
  without leaking provider tokens into skill environment or receipts.
- Documentation paths, relative links, and the documented Rust toolchain
  requirement, with contributions from
  [@lightight](https://github.com/lightight) in
  [#364](https://github.com/runxhq/runx/pull/364),
  [#365](https://github.com/runxhq/runx/pull/365), and
  [#366](https://github.com/runxhq/runx/pull/366).

## Removed

- Runtime coupling to Aster and other external control-plane assumptions from
  the OSS execution path.
- Redundant tool-local shell, HTTP, request, parser, authoring, and registry
  implementations where a native capability is the proven owner.
- Incomplete Cargo publication and unsupported AUR mutation from the CLI
  release contract.
- Silent fallback paths that could bypass declared context, capability,
  approval, or evidence ownership.

## Security

- Updated PostCSS to 8.5.23.
- Resolved vulnerable Fast URI, Vite, and esbuild dependency ranges with
  `fast-uri` 3.1.4, Vite 8.1.5, and esbuild 0.28.1.
- Kept skill subprocess environments allowlisted and credential delivery
  declaration-bound.
- Closed every open Dependabot alert before the release.

## Breaking changes

- Building Runx from source now requires Rust 1.97 or newer; the repository is
  pinned to Rust 1.97.1 for reproducible release builds.
- Internal integrations that depended on the retired Aster execution coupling
  must use the public Runx agent, provider, or connector boundaries.
- No public contract identifier moves to v2 in this release. Existing v1
  consumers continue on the canonical contract family.
- `runx skill --approve-operator-context <digest>` is gone. Prepared operator
  context stays digest-bound evidence on every run, and a consequential action
  stops only at its own graph or provider-effect approval gate.

## Upgrade guidance

- Install the native-backed npm selector with
  `npm install --global @runxhq/cli@0.8.0`, or use the release archives,
  Homebrew, Scoop, `runx.ai/install`, or Winget after its upstream manifest is
  accepted.
- Run `runx --version` and confirm `0.8.0`.
- If you use generated Codex shims, run `runx export codex` after upgrading so
  installed shims reflect the audited 0.8.0 skill manuals and runner topology.
- Re-test project-owned release profiles or private adapters that referenced
  internal runtime paths; public skill and provider contracts remain the
  supported integration boundary.
