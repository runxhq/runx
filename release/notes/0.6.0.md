# Runx CLI 0.6.0

Runx 0.6.0 is the first native release. The CLI and the runtime it drives are
Rust, built per platform and installed as one binary; the TypeScript CLI is
gone. Skills run as graphs under one governed runtime that admits, executes and
seals each step, and every run ends in a content-addressed receipt.

## Highlights

- A native `runx` binary for macOS (Apple silicon and Intel), Linux (x64 and
  ARM64) and Windows x64. `@runxhq/cli` on npm is a launcher that installs the
  binary for the platform it runs on.
- A release pipeline that builds, archives and checksums each platform's
  binary, publishes a container image, renders Homebrew, Scoop and winget
  manifests, and ships install scripts.
- Flat `runx.receipt.v1` receipts: a content-addressed id, the run's decisions
  and acts inline, and verification computed from the receipt itself.
- Contract JSON Schemas generated from the Rust types, with a check that the
  published schemas match what the runtime emits.

## Added

- Graph-backed skill runs, with approvals as native graph steps and a native
  harness for skill fixtures.
- `runx mcp serve`, the governed MCP server, served by the native runtime with
  pooled MCP sessions.
- `runx policy` for operational policies, and `runx dev` for native skill
  fixtures.
- A payment authority gate with typed rail admission, x402 payment proofs, a
  payment ledger, and charge and refund skill profiles.
- A credential delivery channel that records each delivery it observes.
- Paused runs in `runx history`, and invokable graphs under `runx list skills`.

## Changed

- "Chains" are graphs throughout the runtime, contracts and docs.
- Receipts are written to `~/.runx/receipts` by default.
- The repository and packages are licensed under MIT.

## Security

- A skill's sandbox policy is advisory at this release: runx claims no
  operating-system confinement, and a run that requires enforcement fails
  closed. The receipt ledger is tamper-evident.
- Live receipts are stamped with trusted time, and receipt proofs and receipt
  trees are read strictly.
- Install digests a candidate package states are not trusted; the runtime
  computes them.
- Registry and URL fetches time out after 30 seconds by default.

## Breaking changes

- `@runxhq/cli` exports no JavaScript modules. `runCli` and
  `@runxhq/cli/metadata` are gone; read the CLI version from the package's
  `package.json`.
- Receipts from 0.5 are not produced; consumers read `runx.receipt.v1`.
