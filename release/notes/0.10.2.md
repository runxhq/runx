# Runx CLI 0.10.2

Runx 0.10.2 adds bounded native JSON Schema validation, fixes complete package
identity reporting and prevents installed dependencies from being discovered as
independent workspace skills. The bundled foundation works without a registry;
optional skills and connectors remain separately published packages.

## Highlights

- Extraction and contract checking use the same native JSON Schema 2020-12
  validator, with digest-bound results and bounded errors.
- Native package preparation exposes the digest of the complete package,
  including executable modules, references and dependency files.
- Workspace discovery stops at a published bundle boundary, so an exported or
  installed dependency is not listed a second time as another workspace skill.

## Added

- `data.validate` validates up to 128 values against one bounded schema. Results
  include exact schema/value digests and error paths without copying private
  values. External schema retrieval is disabled.
- `runx registry package --json` includes `registry.content_digest`, using the
  same native complete-package identity as publication.
- Native harness `process_calls` replays exact local connector-tool results
  without starting host processes. Unmatched calls fail without a live fallback;
  actual driver behavior is verified separately.
- The optional `sql` connector supports operator-declared parameterized queries
  through installed SQLAlchemy dialects and database drivers. Its dependencies
  are installed on the connector host, separately from the CLI. SQL Analysis
  selects a declared read and interprets actual returned rows.

## Fixed

- Full exports no longer fail because a previously exported package's bundled
  dependencies are rediscovered as separate workspace packages.
- Native integers outside JavaScript's safe range are refused before module
  execution, preventing silent rounding of large identifiers and schema values.
  Exact large values can cross the module boundary as strings.
- Maintained-package locks use complete native package identities, so changes
  to modules and references cannot hide behind unchanged manual/profile bytes.
- Extraction validates actual values; schema checking validates actual samples
  and refuses compatibility comparisons it cannot establish.
- Support triage uses the request, product documentation and support policy
  rather than a keyword classifier or invented confidence score.

## Changed

- Team delegation returns bounded assignments. The host owns continuing work,
  scheduling and child invocation. Operations review defaults to supplied state.
- Coordinate weather reads reuse supplied coordinates rather than geocoding
  them again.
- Process-only credentials may omit a runtime HTTP audience: the bound process
  receives the credential and owns further presentation. Existing process
  descriptors can retain their declared audience. HTTP, command-session and
  hosted uses still require a network audience; store-only credentials still
  declare none. Trusted processes remain host processes, not network sandboxes.
- The companion contracts package adds the native validation result schema.
  The client companion includes the current native inspection/process types and
  decoding fixes, with the matching contracts dependency.

## Removed

- The old SQL Analysis event-store surrogate and package-local partial JSON
  Schema validators in the repaired maintained skills.
- Current catalog aliases for the approved renamed packages. Valid immutable
  historical packages and existing receipt bindings retain their original bytes.

## Security

- Native schema validation cannot retrieve remote schemas and bounds schema,
  value and error sizes. Validation errors contain paths, not rejected values.
- The SQL connector accepts only operator-declared queries and schema-validated
  bound values. Database read-only permissions and server timeouts remain
  operator prerequisites; SELECT parsing and transaction rollback do not prove
  arbitrary database functions are free of effects.

## Breaking changes

- Current registry names change from `agency` to `team-delegate`,
  `content-pipeline` to `content-package`, `contract-drafter` to `contract-draft`,
  `crm-cleanup` to `crm-update-plan`, `data-subject-request` to
  `privacy-request-review`, `deep-research` to `research-brief`, `github-sync` to
  `github`, `helpdesk` to `support-triage`, `issue-intake` to `code-intake`,
  `issue-to-pr` to `github-issue-to-pr`, `issue-triage` to `github-issue-triage`,
  `list-hygiene-judge` to `contact-consent-review`, `nws-weather-forecast` to
  `nws-weather`, `open-meteo-weather-forecast` to `open-meteo-weather`, `ops-desk`
  to `operations-review`, `postmortem-maker` to `postmortem-draft`,
  `purchase-approval` to `purchase-policy-check`, `sbom-maker` to `sbom-generate`,
  `schema-guard` to `schema-check`, `settle-invoice` to `invoice-pay`,
  `sql-analyst` to `sql-analysis`, and `work-plan` to `code-plan`. Publisher
  ownership is unchanged. Update current references and inspect the new runner
  contracts; old current names are not compatibility aliases.
- SQL Analysis takes a logical source reference and question. Its default
  performs an actual declared SQL read. Its explicit plan runner accepts a
  supplied query catalog and reports `executed: false`.
- Core foundation skills come from the CLI bundle. Their redundant current
  registry listings are withdrawn as part of the catalog cutover.

## Upgrade guidance

- Install `@runxhq/cli@0.10.2` or the corresponding native release and verify
  `runx --version` before installing the updated catalog packages.
- Re-export agent bindings from the updated packages. Update graph references
  to the current skill names; historical receipts need no rewriting.
- For SQL, install the optional connector requirements and chosen database
  driver, bind an operator-owned read-only source and declare useful queries.
  No database driver is bundled into the CLI.

## Contributors

Community package updates retain their original publisher identities and
contributor attribution. Maintained packages remain published by Runx.
