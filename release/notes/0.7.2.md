# Runx CLI 0.7.2

Runx 0.7.2 finishes the native runtime cutover, makes credentials and the
managed agent explicit, and renames skills to the jobs they do.

## Highlights

- The last TypeScript CLI paths are gone: every command runs on the native
  runtime, with agent output contracts, profile evidence, local operator state
  and deterministic environment resolution enforced there.
- First-class skill credentials: a skill names the credentials it needs, local
  profiles are encrypted, and each credential is delivered at the adapter
  boundary for skill, resume, MCP and exported runs.
- The managed agent runs only with explicit consent: `--managed-agent`, with a
  per-run round limit, across skill, resume, graph and MCP runs. A configured
  model credential never starts a model loop on its own.

## Added

- A governed Nitrosend provider adapter.
- Skill, resume and MCP runs load a workspace `.env` once, keeping process
  precedence and sandbox allowlists, and resolve credential profiles from the
  same snapshot.
- Tool processes can run on Node 24, within their declared bounds.
- Runx CLI releases run through the governed release skill.

## Changed

- Nine skills are named for their jobs: `ghostwrite`, `helpdesk`,
  `chief-of-staff`, `extract`, `deep-research`, `audit-receipt`,
  `least-privilege`, `run-history` and `overlay`.
- The security skills are one chain: `cve-audit`, then `vuln-triage`, then
  `vuln-disclosure`.
- Human approval is required only when the selected graph mutates state;
  prepared context stays digest-bound for every run.
- Help and failure output share one contract, and the synchronous HTTP runtime
  is reused across calls.

## Fixed

- The Windows receipt store no longer fsyncs a directory, which Windows
  refuses.
- An unusable Linux sandbox is detected instead of failing mid-run.
- An inline harness case is held to the runner's required inputs.
- A multi-runner skill exports without inventing a default runner.

## Removed

- Legacy graph input bindings.

## Breaking changes

- Renamed skills: `draft-content` is `ghostwrite`, `support-triage-reply` is
  `helpdesk`, `inbox-and-calendar-exec` is `chief-of-staff`,
  `structured-extraction` is `extract`, `deep-research-brief` is
  `deep-research`, `receipt-auditor` is `audit-receipt`,
  `least-privilege-auditor` is `least-privilege`, `run-history-analyst` is
  `run-history`, and `overlay-generator` is `overlay`.
- A run that uses the managed agent passes `--managed-agent`.
