# Runx CLI 0.9.1

Runx 0.9.1 fixes Windows child-process startup from canonical working
directories and brings the public first-receipt documentation back into line
with the shipped CLI and receipt contracts. It also carries reviewed runtime,
transport, cryptography and JSON Schema dependency updates.

## Highlights

- Node-backed skills now start correctly when Runx canonicalizes a short
  Windows working directory to an extended-length path.
- The first-receipt guide now covers Bash and PowerShell with the actual 0.9
  command surface and receipt inspection schema.

## Added

- Windows CI proof that launches Node from a canonical temporary directory,
  alongside direct drive-path, UNC-path and long-path coverage.

## Changed

- Updated `jsonschema` to 0.55.1 and refreshed compatible `syn`, `aes-gcm`,
  `rmcp` and `hyper` releases after Linux and Windows validation.
- Updated the Vitest development toolchain to 4.1.11.
- Updated the release install action used by CI.

## Fixed

- Child process launches normalize short Windows verbatim drive and UNC paths
  at the spawn boundary while retaining verbatim form for long-path safety.
- The public credentials guide link now targets the actual OSS repository path.
- Receipt examples now distinguish a sealed skill result from the closed
  receipt returned by detailed history inspection.

## Removed

- Documentation for the nonexistent `runx export-receipts --trainable`
  command and its unsupported training-export claim.

## Security

- Runtime dependency maintenance includes current cryptography, HTTP transport,
  MCP and schema-validation fixes without widening Runx authority or provider
  boundaries.
- Vitest and its mocker include the fix for GHSA-82fw-gwwq-j7x9 in the local
  test toolchain.

## Breaking changes

- None. This patch preserves the 0.9 command, skill and receipt contracts.

## Upgrade guidance

- Install with `npm install --global @runxhq/cli@0.9.1`, Homebrew, Scoop, or the
  matching release archive, then confirm `runx --version` reports `0.9.1`.
- Windows users running Node-backed skills should upgrade from 0.9.0.

## OCI image correction (2026-10-08)

The original `ghcr.io/runxhq/runx:0.9.1` image omitted `runx-js-worker`, so
JavaScript skills cannot run from that image. The published CLI archives are
unaffected. Use `ghcr.io/runxhq/runx:0.9.1-r1` (digest
`sha256:976fbbc1b22a55eaaeb1549e8b11bfd68bdaf2bef174df1841c998ab53e0debb`) for
container installs. That repaired amd64/arm64 image ran a JavaScript skill and
sealed a receipt on native runners. The original image tag remains unchanged.
