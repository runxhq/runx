# Receipts Reference

Use `receipt-query` for exact ids or explicit bounded receipt filters,
`receipt-audit` for governance against an exact evidence baseline,
`run-history` for bounded deterministic run outcomes, and `least-privilege`
for authority review with actual usage/policy evidence. Inspect native receipt
verification when signature or tree integrity is the question.

A local receipt proves what this Runx home recorded and signed. It does not
independently establish provider identity, source truth, settlement or delivery.
A supplied summary or replay projection is not a fresh verification result.
Keep absent, failed and unchecked verification distinct.

For each proposed verification retain the exact receipt/effect reference,
expected outcome, trust boundary and independent provider readback where needed.
Inspect native retained claims only with their actual read authority. Never
request whole private bodies when a redacted projection answers the question.

Receipt publication/notarization is a separate explicit operation, not a
verification side effect. Do not publish private evidence or infer that no
action occurred merely because a receipt is absent. Operations review reasons
over supplied evidence; it does not perform these readers or verifiers itself.
